# Contributing — Jupytext Percent-Format Workflow

Detailed operational reference for [`CLAUDE.md`](CLAUDE.md)'s single most important rule.

---

## Source of truth

Every notebook under `nbs/` (and `CRAFT.ipynb` / `CRAFTs/*.ipynb`) is paired via
[Jupytext](https://jupytext.readthedocs.io/) with a `.pct.py` file of the same name in
`py:percent` format (`# %%` cell markers), configured in `pyproject.toml`:

```toml
[tool.jupytext]
formats = "ipynb,.pct.py:percent"
```

The leading dot before `pct` matters — `pct.py` (no dot) produces a filename with no
separator (`callbackspct.py`, wrong); `.pct.py` correctly produces `callbacks.pct.py`.

**Edit the `.pct.py` file. Never edit the `.ipynb` JSON directly.** Both `.pct.py` and
`.ipynb` are git-tracked. The `.ipynb` is not gitignored — it's kept so anyone can open
and read a notebook straight from GitHub or a Jupyter GUI without needing the Jupytext
CLI — but it is a Jupytext-managed mirror of the `.pct.py`, not an independent editing
surface.

## Required sync points

| When | Command |
|------|---------|
| Session startup / after a branch switch / after any external change to `.ipynb` files | `jupytext --sync **/*.ipynb` |
| Immediately after creating or editing any paired `.pct.py` file | `jupytext --sync <path/to/file.pct.py>` |

(`jupytext` may not be on `PATH` depending on the environment — use `python -m jupytext ...` if the bare command isn't found.)

## `.pct.py` percent format ≠ the installed package

Three files can share a base name — do not confuse them:

- `nbs/handlers/fram_strait2025.pct.py` — the Jupytext-paired **source**. Edit this.
- `nbs/handlers/fram_strait2025.ipynb` — Jupytext-managed mirror, git-tracked for GUI access. Never edit directly.
- `marisco/handlers/fram_strait2025.py` — the **nbdev-exported package module** that `import marisco...` actually loads. Never edit this directly (still carries `# AUTOGENERATED! DO NOT EDIT!`).

Jupytext only keeps `nbs/*.pct.py` ⇄ `nbs/*.ipynb` in sync — it does not replace nbdev's
export step. After syncing your `.pct.py` edits into the notebook, `nbdev_export` still
has to run to regenerate the importable `marisco/` package from the now-updated notebook
(`#| export` cell markers, `_modidx.py`, etc.):

```console
jupytext --sync nbs/handlers/fram_strait2025.pct.py   # 1. .pct.py -> .ipynb
nbdev_export                                           # 2. .ipynb -> marisco/*.py (unchanged mechanism)
```

If this two-step handoff turns out not to match the intended end state, flag it —
the alternative (dropping the nbdev export step entirely and importing straight from
`nbs/`) is a materially bigger change to how the package is built and hasn't been
confirmed.

## Tooling target

Point static analysis and context-generation tooling at the paired `.pct.py` files, not
the `.ipynb` or `*.context.md` companions:

```console
ruff check .
mypy .
```

`tools/compile_notebook_context.py` still reads notebooks as of this writing — retargeting
it to the `.pct.py` percent files is a follow-up, not yet done.

## Migration notes

**2026-07-23, initial migration:** the first repo-wide `jupytext --sync **/*.ipynb` run
found that several `nbs/**/*.py` percent-format files already existed on disk, untracked,
predating this policy — most with lint cleanup already applied (unused imports removed,
minor style fixes). Syncing pulled that pre-existing work into the corresponding
notebooks. Every touched notebook was spot-checked for symbol usage before/after; no
in-use symbol was dropped.

**2026-07-23, `.pct.py` rename:** the pairing suffix was changed from plain `.py` to
`.pct.py` to remove ambiguity with `marisco/*.py` (nbdev output). The first attempt at
this used `formats = "ipynb,pct.py:percent"` (missing the leading dot before `pct`),
which silently produced malformed filenames with no separator (`callbackspct.py` instead
of `callbacks.pct.py`) across all 55 notebooks. This was caught before committing,
corrected to `formats = "ipynb,.pct.py:percent"`, the malformed files deleted, and every
notebook re-synced under the corrected format. The old unsuffixed `.py` siblings from the
initial migration were deleted once the properly-named `.pct.py` files were confirmed
present for all 55 notebooks.

If a notebook you rely on looks different than expected, `git diff` it against the
previous commit before assuming your work is intact.
